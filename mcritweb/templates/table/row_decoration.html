{#- Row-specific rendering for table rows - issue #53. A view hands a table macro `row_decorations`: a mapping of row id to a decoration dict. `_table_base` forwards it to the row *and* the header macro, so both sides of a table stay in step without the caller repeating itself. A row macro looks itself up by the id it already renders - sample_id, family_id, function_id. row_decorations = {23: {"tint": "selected", "badges": [{"text": "ID match", "variant": "success"}]}} Both keys are optional. `tint` colours the whole row, `badges` puts Bootstrap badges in an extra leading column that only exists while some row has one. Tints and badge variants are *names looked up here*, never interpolated: rows carry values chosen by whoever submitted the sample, and a decoration able to carry raw CSS or a raw class name would be a way to restyle the page from a corpus entry. An unknown name renders nothing. Badge text is ordinary autoescaped output. A tint is a *class name*, not a colour. It was a colour until issue #70 tokenised the palette: a literal in a style attribute cannot follow the theme, and `testTheme.test_no_template_spells_out_a_colour` refuses one. `tr.row-selected` and `tr.row-pending` in `static/style.css` carry the two shades per theme, and the class is also what cross_compare's own click handler reads back off a row. -#} {#- "selected" and "pending" are the two states cross_compare.html has always shown; both palettes define them once, in style.css. -#} {%- set ROW_TINTS = {"selected": "row-selected", "pending": "row-pending"} -%} {%- set BADGE_VARIANTS = ["primary", "secondary", "success", "danger", "warning", "info", "light", "dark"] -%} {#- a class name for the enclosing , written *inside* its class attribute so it stays empty when nothing is decorated and never grows a second attribute -#} {%- macro row_tint(row_decorations, row_id) -%} {%- set tint = ROW_TINTS.get((row_decorations or {}).get(row_id, {}).get("tint")) -%} {%- if tint %} {{ tint }}{% endif -%} {%- endmacro -%} {%- macro row_badges(row_decorations, row_id) -%} {%- for badge in (row_decorations or {}).get(row_id, {}).get("badges", []) -%} {{ badge["text"] }} {% endfor -%} {%- endmacro -%} {#- The badge column appears only once some row actually has a badge, otherwise every table that passes tints alone would grow an empty column. Header and row ask the same question of the same mapping, so they cannot disagree on the column count. -#} {%- macro badge_column_header(row_decorations) -%} {%- if (row_decorations or {}).values()|selectattr("badges")|list %}{% endif -%} {%- endmacro -%} {%- macro badge_column_cell(row_decorations, row_id) -%} {%- if (row_decorations or {}).values()|selectattr("badges")|list %}{{ row_badges(row_decorations, row_id) }}{% endif -%} {%- endmacro -%}
